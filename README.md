## 🎯 1. О Проекте

### 1.1. Цель
Создание современного, адаптивного, юридически корректного зеркала сайта `https://sit-salsk.ru/` для ГБПОУ РО "СИТ" (Сальский индустриальный техникум).

### 1.2. Требования к схожести
- **Минимум 70%** визуальной и структурной схожести с оригиналом (учитывая объем >10,000 файлов).
- Приоритет: **функциональная идентичность** > пиксель-перфект.
- Все изменения дизайна должны улучшать юзабилити, не ломая привычную навигацию пользователей.

### 1.3. Соответствие нормам РФ
Структура и содержание разделов должны соответствовать:

| Норма | Описание |

| ♿ ГОСТ Р 52872-2019 | Доступность для слабовидящих (версия с увеличенным шрифтом, контрастом) |
| 🔐 152-ФЗ "О персональных данных" | Согласие на обработку, политика конфиденциальности |
| 📚 273-ФЗ "Об образовании" | Публикация сведений об образовательной организации |

## ⚙️ 2. Глобальные принципы разработки

### 2.1. Адаптивная вёрстка (Mobile First)
- Все компоненты разрабатываются сначала для мобильных устройств
- Используются брейкпоинты Bootstrap 5: `sm:576px`, `md:768px`, `lg:992px`, `xl:1200px`
- Нет горизонтального скролла на мобильных
- Область нажатия интерактивных элементов ≥44×44px

### 2.2. Единые компоненты (DRY)
- Шапка (`header.njk`) и подвал (`footer.njk`) — единые для всех страниц
- Изменение в одном файле обновляет весь сайт
- Компоненты хранятся в `src/_includes/partials/`

### 2.3. Доступность (WCAG 2.1 AA)
- ♿ Переключатель «Версия для слабовидящих» (шрифт, контраст, анимации)
- 🧭 Семантическая разметка: `<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`
- ⌨️ Навигация с клавиатуры (Tab, Enter, Esc)
- 🔤 Все изображения имеют `alt`-тексты

### 2.4. Управление файлами
> ⚠️ **Важно:** Папка `public/` — артефакт сборки. Она генерируется автоматически и **не должна коммититься** в репозиторий.

Файл `.gitignore` исключает:
```
public/
node_modules/
*.log
.env
.DS_Store
```

## 🚀 4. Быстрый старт

### Требования
- Node.js 18+
- npm 8+
- Git

### Установка и запуск
```bash
# 1. Клонировать репозиторий
git clone git@github.com:DimaNikolaevi4/site.git
cd site

# 2. Установить зависимости
npm install

# 3. Запустить локальный сервер разработки
npm run dev
# Сайт доступен по адресу: http://localhost:8080

# 4. Собрать продакшн-версию
npm run build
# Результат в папке: public/
```

### Основные команды
```bash
npm run dev      # Запуск сервера разработки с авто-обновлением
npm run build    # Сборка продакшн-версии в public/
npm run serve    # Запуск локального сервера для собранной версии
```

## 📤 5. Деплой на BeGet

### Текущий процесс (для <100 страниц)

```bash
# Переход в корневую директорию сайта (расположена в домашнем каталоге пользователя)
cd ~/sit-saljsk.rf

# Запуск скрипта деплоя, который лежит прямо в корне сайта
./deploy.sh

**Что делает скрипт:**
1. ✅ Клонирует репозиторий во временную папку `temp-build`
2. ✅ Устанавливает зависимости: `npm ci --omit=dev`
3. ✅ Собирает проект: `npm run build`
4. ✅ Очищает `public_html/` (сохраняя `submit-form.php`, `.htaccess`, логи)
5. ✅ Копирует новые файлы из `public/` в `public_html/`
6. ✅ Устанавливает правильные права доступа (644 для файлов, 755 для папок)
7. ✅ Удаляет временные файлы

> ⚠️ **Примечание:** При количестве страниц >100 рекомендуется перейти на оптимизированный деплой (см. раздел 6).

### Ручная проверка после деплоя
```bash
# 1. Открыть сайт в браузере
✅ https://сит-сальск.рф/

# 2. Проверить ключевые функции
✅ Навигация работает
✅ Поиск находит материалы
✅ Форма отправляет данные
✅ Переключатель доступности меняет стили
✅ Страница 404 отображается корректно

# 3. Проверить системные файлы
✅ /robots.txt доступен
✅ /sitemap.xml сгенерирован
✅ /submit-form.php исполняется (не скачивается)
```

## ⚡ 6. Оптимизация на будущее

> 📌 **План:** При росте количества страниц (>100) или увеличении времени сборки (>3 мин) перейти на оптимизированный процесс деплоя.

### 🔹 Этап 1: Замена `cp` на `rsync` (минимальные изменения)

**Заменить в `deploy.sh`:**
```bash
# ❌ Было (копирует всё):
cp -r ~/sit-saljsk.rf/temp-build/public/* ~/sit-saljsk.rf/public_html/

# ✅ Стало (только изменённые файлы):
rsync -av --checksum --delete \
  --exclude='submit-form.php' \
  --exclude='forms.log' \
  --exclude='.htaccess' \
  ~/sit-saljsk.rf/temp-build/public/ \
  ~/sit-saljsk.rf/public_html/
```

**Преимущества:**
- ⚡ Копируются только реально изменённые файлы (сравнение по контрольной сумме)
- 🗑️ Автоматически удаляются удалённые в репозитории файлы
- 📉 Меньше I/O нагрузки на хостинг

### 🔹 Этап 2: Гибридный деплой (сборка в GitHub Actions)

**Идея:** Тяжёлую сборку выполнять в облаке, на хостинг загружать только артефакты.

**Преимущества:**
- 🚀 Сборка на мощностях GitHub (не нагружает Beget)
- ⏱️ Деплой занимает секунды, а не минуты
- 🔄 Автоматизация: пуш в `main` → авто-деплой
- 📜 История деплоев в GitHub Actions

**Файл:** `.github/workflows/deploy.yml` (будет добавлен при переходе)

### 🔹 Этап 3: Исключение старых страниц из сборки

**Идея:** Страницы, не менявшиеся >30 дней, не пересобирать при каждом деплое.

**Реализация:**
1. Добавить в front matter дату последнего изменения:
   ```yaml
   ---
   title: Устав техникума
   lastModified: 2024-01-15
   skipBuildIfOlderThan: 30
   ---
   ```
2. Фильтр в `.eleventy.js` для пропуска старых страниц
3. Кэширование уже сгенерированных HTML-файлов

> ⚠️ **Осторожно:** Инкрементальная сборка в Eleventy имеет ограничения. Тестировать перед использованием в продакшене.

### 📊 Критерии перехода на оптимизацию

```
⚠️ Переходить на оптимизированный деплой, если:
[ ] Количество страниц > 100
[ ] Время сборки на хостинге > 3 минут
[ ] Нагрузка на CPU/RAM во время деплоя вызывает предупреждения
[ ] Трафик или место на диске становится ограничивающим фактором
```
