## 1. О Проекте

### 1.1. Цель
Создание современного, адаптивного, юридически корректного зеркала сайта `https://sit-salsk.ru/` для ГБПОУ РО "СИТ" (Сальский индустриальный техникум).

### 1.2. Директория /mirror — Зеркало сайта

**Назначение**: Директория `/mirror` содержит точную копию структуры рубрик сайта sit-salsk.ru, организованную в соответствии с Приказом Рособрнадзора №1493 и рубрикатором WordPress оригинального сайта.

**Принцип организации**:
- Каждая папка соответствует категории WordPress (`?cat={ID}`)
- В каждой папке находится `index.html` — скачанная страница категории
- Полное соответствие навигации «Выберите нужный раздел/рубрику сайта»

**Структура**:
```
mirror/
├── {N}_{SECTION}/              # 10 основных разделов
│   ├── index.html              # HTML категории
│   ├── {N.N}_{SUBSECTION}/     # Подразделы уровня 1
│   │   └── index.html
│   └── {N.N.N}_{SUBSUBSECTION}/# Подразделы уровня 2
│       └── index.html
├── unsorted/                   # Технические файлы
├── SITE_RUBRICS_STRUCTURE.md   # Документация структуры
├── MIRROR_README.md            # Описание назначения
└── CHECKLIST.md                # Аудит заполненности
```

**Взаимосвязь с другими директориями**:
- `/src` — исходный код Eleventy, использует контент из `/mirror` для шаблонов
- `/public` — результат сборки (`npm run build`), **АРТЕФАКТ**, не редактируется вручную

**Подробнее**: см. `/mirror/MIRROR_README.md`

## 2. Глобальные принципы разработки

### 2.1. Адаптивная вёрстка (Mobile First)

```css
/* Базовый подход: стили для мобильных → медиа-запросы для больших экранов */
.component {
  /* Мобильные стили по умолчанию */
  padding: 1rem;
  font-size: 1rem;
}

/* Планшеты */
@media (min-width: 768px) {
  .component {
    padding: 1.5rem;
    font-size: 1.125rem;
  }
}

/* Десктопы */
@media (min-width: 1024px) {
  .component {
    padding: 2rem;
    font-size: 1.25rem;
  }
}
```

**Контрольные точки (Breakpoints Bootstrap 5):**
| Брейкпоинт | Ширина | Устройство |
|------------|--------|------------|
| `xs` | <576px | Малые телефоны |
| `sm` | ≥576px | Телефоны |
| `md` | ≥768px | Планшеты |
| `lg` | ≥992px | Ноутбуки |
| `xl` | ≥1200px | Десктопы |
| `xxl` | ≥1400px | Большие экраны |

**Требования:**
- ✅ Все компоненты тестируются на всех брейкпоинтах
- ✅ Нет горизонтального скролла на мобильных
- ✅ Область нажатия интерактивных элементов ≥44×44px на мобильных
- ✅ Шрифты масштабируются через `clamp()`: `font-size: clamp(1rem, 2.5vw, 1.5rem);`

### 2.2. Единые компоненты (DRY — Don't Repeat Yourself)

> ⚠️ **Важно:** Директория `partials/` не используется. Все компоненты перемещены в `components/`.

Вся шапка, подвал, сайдбар и повторяющиеся блоки страниц вынесены в отдельные компоненты Nunjucks, расположенные в `src/_includes/`. Это обеспечивает единообразие на всём сайте: изменение в одном файле автоматически обновляет соответствующий блок на всех страницах.

Подробный перечень компонентов и их соответствие 8 секциям архитектуры приведён в **пункте 3.5**.

### 2.3. Доступность (Accessibility / WCAG 2.1 AA)

**Обязательные требования:**
- 👁️ Переключатель «Версия для слабовидящих»:
  - Увеличение шрифта (1.25×, 1.5×, 2×)
  - Высококонтрастная тема (чёрный фон / белый текст / жёлтые ссылки)
  - Отключение анимаций и переходов
  - Сохранение выбора в `localStorage`
- 🧭 Семантическая разметка:
  ```html
  <header>, <nav>, <main>, <article>, <aside>, <footer>
  ```
- ⌨️ Навигация с клавиатуры:
  - `Tab` — переход между интерактивными элементами
  - `Enter` — активация ссылки/кнопки
  - `Esc` — закрытие модальных окон, меню
  - Видимый фокус-индикатор для всех элементов
- 🔤 Альтернативные тексты:
  ```html
  <img src="logo.png" alt="ГБПОУ РО 'СИТ' — логотип техникума">
  ```

**Инструменты проверки:**
- [WAVE Web Accessibility Tool](https://wave.webaim.org/)
- [axe DevTools](https://www.deque.com/axe/devtools/)
- Lighthouse → Accessibility (цель: ≥95)

### 2.4. Стили: единый источник правды

> ⚠️ **Канонический CSS проекта — `src/styles/main.css`.** Это единственный файл стилей, подключаемый на всех страницах сайта.

**Правила:**

- ✅ **Подключение.** В `src/_includes/layouts/base.njk` стоит ровно одна строка `<link>` на стили проекта:
  ```html
  <link rel="stylesheet" href="/styles/main.css">
  ```
  Папка `src/styles/` копируется в `public/styles/` через `eleventyConfig.addPassthroughCopy("src/styles")` (см. `.eleventy.js`).

- ❌ **Запрещено.** Создавать параллельные «вторые» CSS-файлы (`src/assets/css/style.css`, `src/assets/css/extra.css` и т. п.) и подключать их в шаблоны. Любые новые правила добавляются **только** в `src/styles/main.css`.

- 🗂️ **Статус `src/assets/css/style.css`.** Файл считается **устаревшим (deprecated)** и подлежит удалению после завершения миграции уникальных правил в `main.css` (см. задачи 2.7.2–2.7.4 в `CHECKLIST.md`). До завершения миграции файл может физически присутствовать в репозитории, но **не должен подключаться ни одним шаблоном** (`rg 'assets/css/style\.css' src` обязан давать 0 совпадений).

- 🧱 **SCSS-исходники в `src/assets/scss/`.** Зарезервированы для будущей сборки через препроцессор. На текущий момент `main.css` редактируется напрямую как plain CSS.

- 🔍 **Проверка после правок стилей.** После любого изменения `main.css` обязательно прогнать `npm run build` и убедиться, что главная и одна-две внутренние страницы (например, `/svedenija/`, `/abiturientam/`) визуально не сломаны.

**Почему канонический файл — `main.css`, а не `style.css`:**
1. `main.css` уже подключён в `base.njk` → активен на всех страницах.
2. Объём правил больше (~7 200 строк против ~5 400) и они актуальнее.
3. Файл `style.css` оставлен от предыдущей итерации шаблона, ни один шаблон на него не ссылается → его правки не влияют на сайт и порождают класс ошибок «правлю — ничего не меняется».

### 2.5. Папка `public/` — генерируемая директория, руками не править

> ⚠️ **Папка `public/` — выходная директория Eleventy.** Она целиком перезаписывается на каждом запуске `npm run build` (и на каждой пересборке в режиме `npm run dev`). Любые ручные правки в `public/` теряются при следующей сборке.

**Правила:**

- ❌ **Запрещено** редактировать что-либо внутри `public/` напрямую — ни HTML (`public/index.html`, `public/svedenija/index.html`, …), ни скопированные ассеты (`public/styles/main.css`, `public/images/…`, `public/assets/…`).
- ✅ **Все изменения вносятся только в `src/`.** Источники по типам:
  - HTML-разметка → `src/_includes/layouts/`, `src/_includes/components/`, `src/index.njk`, `src/pages/`, `src/content/`
  - Стили → `src/styles/main.css` (см. § 2.4)
  - JS → `src/assets/js/` (passthrough в `public/assets/js/`)
  - Изображения и медиа → `src/images/`, `src/assets/images/`, `src/assets/uploads/`
  - Фавиконы и манифест → `src/assets/favicons/`
- 🔁 **Как увидеть изменения.** В режиме разработки (`npm run dev`) Eleventy следит за `src/` и пересобирает `public/` автоматически — правка в `src/` сразу отражается в браузере. Для контроля «как пойдёт на прод» — `npm run build` и просмотр `public/` целиком.
- 🚫 **`public/` не коммитится в Git.** В `.gitignore` уже указано `public/` (строка 5) — артефакт сборки в репозитории не нужен. Воспроизводимая сборка восстанавливается из `src/` командой `npm run build` на любом окружении (локально, в Replit, на CI, на сервере во время `deploy.sh`).
- 🛠️ **Деплой.** Скрипт `deploy.sh` сам выполняет `npm run build` на сервере и копирует свежий `public/` в `public_html` хостинга — содержимое `public/` из репозитория для деплоя не используется.

**Класс ошибок, который закрывает это правило:**

> «Правлю `public/index.html` — ничего не меняется на следующей сборке.»

Действительно: следующая команда сборки (или watch-итерация) перезаписывает файл из соответствующего шаблона/контента. Найти источник конкретной строки в `public/` можно через `rg "<уникальный кусок текста>" src/`.

## 3. Архитектура страниц: 8 секций, 3 типа (v3.0 — ФИНАЛЬНАЯ)

> **Статус:** Согласовано, апрель 2026. Все шаблоны и md-файлы привязаны к этой архитектуре.

Сайт построен на **8 фиксированных секциях** и **3 типах страниц**. Шапка (1) и Подвал (8) одинаковы везде. Секции 2–7 управляются через тип страницы.

---

### 3.1. Каталог секций

| № | Секция | Компонент | Описание |
|---|--------|-----------|----------|
| 1 | **Шапка** | `components/header.njk` | Логотип, навигация, контакты, поиск — **единая на всём сайте** (один файл, подключается через `base.njk`, без условного рендера по типу страницы; меняется только класс `active` у текущего пункта меню) |
| 2 | **Хлебные крошки** (внутри `section-context`) | `components/breadcrumbs.njk` | Навигационная цепочка: Главная → Раздел → Подраздел. Секция `section-context` содержит **только хлебные крошки** (плюс `<h1>`, если `showHero: false`). Никаких фильтров, сортировок и баннеров раздела в этой секции **нет** — эти блоки удалены из канона. |
| 3 | **Hero** | `components/hero.njk` | **единая на всём сайте** (один файл, подключается через `base.njk`, без условного рендера по типу страницы; меняется только Блок ГБПОУ РО / СИТ + название рубрики под чертой (только для разделов) / название материалов (только для материалов) |
| 4 | **About** | `components/about.njk` | На главной — слово директора. На разделах — пустая заглушка |
| 5 | **Материалы** | `components/news.njk` | На главной — 3 последних новости. На разделах — 3 превью подрубрик |
| 6 | **Популярное** | `components/popular.njk` | Блок популярных/важных ссылок. Заглушка на всех страницах |
| 7 | **Сайдбар** | `components/sidebar.njk` | ~30% (от 3, 4, 5, 6 секции, между 2 и 8 секцией на всю высоту) левая колонка . **Единые баннеры** — одинаковые на всём сайте (НЕ навигация) Заглушка на всех страницах|
| 8 | **Подвал** | `components/footer.njk` | Реквизиты, контакты, ссылки — **единый на всём сайте** |

---

### 3.2. Три типа страниц

#### Тип A — Главная (`src/index.njk`)

Все 8 секций. Hero без названия рубрики (только «ГБПОУ РО "СИТ"»). Секция About — слово директора. Секция Материалы — 3 последних новости.

```
[1 Шапка] → [3 Hero (полный)] → [4 About (слово директора)] →
[5 Материалы (3 новости)] → [6 Популярное] → [7 Сайдбар] → [8 Подвал]
```

> Секция 2 (хлебные крошки) отсутствует — главная не нуждается в навигационной цепочке.

---

#### Тип B — Раздел (`layout: layouts/page-full.njk`)

**Уровень 0** (основной раздел: Абитуриентам, Сведения, Воспитание…) и  
**Уровень 1** со вложенным **Уровнем 2** (подрубрики).

Все 8 секций. Hero добавляет название рубрики под горизонтальной чертой. Секция «Контекст» (под Hero) содержит **только хлебные крошки**. Секция About — режим `razdel` (пара баннеров «Народный фронт» + «О заключении контракта»). Секция Материалы — превью подрубрик (Level 1 → Level 2).

```
[1 Шапка] → [3 Hero (рубрика)] → [2 Хлебные крошки (section-context)] →
[4 About (razdel)] → [5а Сайдбар (sticky 30%) + 5б Контент + 6 Подрубрики] →
[7 Популярное] → [Backnav] → [8 Подвал]
```

**Канонический шаблон** — `layouts/page-full.njk` (все 11 разделов сайта).  
**Упрощённый вариант** — `layouts/page.njk` (для статических страниц без всех 8 секций).  
**Спец-вариант** — `layouts/svedenija-page.njk` (для раздела «Сведения об ОО»).

**Front matter Type B (минимальный, без вариантов):**
```yaml
layout: layouts/page-full.njk
title: Название раздела
permalink: /slug/
rubric: "1"               # L0: "1" / L1: "1.3" / L2: "2.4.1"
```

#### Тип C — Материал и 404 (`layout: layouts/post.njk` / `layouts/base.njk`)

`post.njk` реализован с **полным функционалом**: Hero — единый, рендерится в `base.njk` (под чертой выводится `title` материала); секция-контекст содержит **только хлебные крошки** + мета материала (никаких фильтров и баннера раздела); сетка 70/30 с сайдбаром, обложка, вложения, теги, шаринг, блок «читайте также», навигация.

Только секции 1, 2 (хлебные крошки в `section-context--post`), 3 Hero (с названием материала), 4 сам материал с тегами, 5 («Читайте также»), 8.

> **Шапка (Секция 1)** на страницах Тип C и 404 — **тот же самый** `components/header.njk`, что и на главной. Он подключается ровно один раз в `base.njk`, поэтому DOM шапки на всех типах страниц идентичен (отличается только пометка активного пункта меню).

```

[Контент] → [Читайте также] → [8 Подвал]
```

**Front matter для Type C:**
```yaml
layout: layouts/post.njk
title: Название материала
date: 2026-04-17
tags: [Новости]
```

### 3.6. Канон страницы раздела (Type B) — единый эталон

> **Эталон:** `/abiturientam/` → `src/content/abiturientam/index.md`.  
> **Применимость:** все **11 разделов сайта** (Type B верхнего уровня и подразделы L1/L2 при необходимости).  
> **Зачем:** редакторы и разработчики имеют один-единственный шаблон страницы раздела — без вариантов, без «кастомных» лейаутов, без скрытых полей.

#### 3.6.1. Frontmatter (метаданные страницы)

```yaml
title: Абитуриентам                      # H1 страницы и <title> в браузере

rubric: "1"                              # Код рубрики из src/_data/rubrics.yaml

  key: abiturientam
  parent: main
  order: 1
tags:
  - Абитуриентам

```

#### 3.6.2. Что автоматически рендерит `layouts/page-full.njk`

| № | Секция | Источник | Управление через frontmatter |
|---|--------|----------|------------------------------|
| 1 | **Header** | `components/header.njk` (в `base.njk`) | — |
| 2 | **Hero** «ГБПОУ РО / СИТ + название раздела» | `components/hero.njk` (в `base.njk`) | `showHero: false` чтобы скрыть |
| 3 | **Контекст: только хлебные крошки** | `components/breadcrumbs.njk` | — (фильтры и баннер раздела удалены из канона) |
| 4 | **About** (правая колонка, элемент 1) | `components/about.njk` | `aboutMode: razdel` (фиксированно для всех 11 разделов) |
| 5а | **Sidebar 30%** (левая колонка, sticky на всю высоту) | `components/sidebar.njk` | `showSidebar: false` чтобы убрать |
| 5б | **Основной контент** (правая колонка, элемент 2) | `<article class="page-content">{{ content \| safe }}</article>` | сюда попадает всё тело Markdown |
| 6 | **Подрубрики** (правая колонка, элемент 3) | `components/news.njk` (`newsMode='subrubrics'`) | автогенерация из `rubric`; **отключено** через `suppressSubrubrics: true` |
| 7 | **Популярные разделы** | `components/popular.njk` | `popularLinks` |
| — | **Backnav** (возврат к родителю + пред/след) | `section-backnav` | автоматически по `section` |
| 8 | **Footer** | `components/footer.njk` (в `base.njk`) | — |

#### 3.6.3. Структура тела Markdown

```
1. # Заголовок раздела                    (H1 = title)

2. <img …приветственная картинка…>        (баннер раздела, опц.)

3. Приветственный блок (2–4 коротких параграфа)

4. {# Полезные материалы — подрубрики раздела #}
   {% set newsMode = 'subrubrics' %}
   {% set newsCollection = "<КОД>" | getSubrubricCards(collections) %}
   {% set excludeUrls = ["…urls для ручного размещения ниже…"] %}
   {% include "components/news.njk" %}

5. Завершающий смысловой параграф

6. ## Ключевая информация раздела          (H2)

7. ## Контакты блока                       (H2)

8. <section class="component-news--subrubrics">
     <ul class="rubric-resources-grid">
       <li>📞 Карточка-контакт раздела</li>
       <li>✉️ Карточка-CTA (mailto / форма)</li>
     </ul>
   </section>
```

#### 3.6.4. Что повторяется одинаково на всех 11 разделах

- `layout: layouts/page-full.njk` — без вариантов.
- `aboutMode: razdel` — пара баннеров сбоку.
- `suppressSubrubrics: true` + ручной вызов `news.njk` в теле — чтобы сетка подрубрик стояла **между приветственным текстом и ключевой информацией**, а не в самом низу.
- Сайдбар слева (`showSidebar: true` по умолчанию) — sticky на всю высоту блока.
- Hero, хлебные крошки, backnav — автоматически.
- Финальный CTA-блок — карточками `rubric-resource` в той же сетке (никаких `btn-primary` на длинных страницах разделов).

#### 3.6.5. Что меняется от раздела к разделу

- `title`, `description`, `permalink`, `rubric`, `section`, `sectionTitle`, `eleventyNavigation.key/order`, `tags`
- `subrubricTitle` (например, «Полезные материалы», «Документы и положения», «Памятки и инструкции»)
- Приветственная картинка (`/assets/images/privetstvie-…-2026.png`)
- Текст приветствия и завершающего параграфа
- Список ключевой информации (что важно для конкретного раздела)
- Состав финальных карточек (контакты + CTA, специфичные для раздела)

## 5. Поисковая система

Реализуется **четыре уровня поиска** на базе Lunr.js:

### 5.1. Общий поиск (Global Search)
- **Расположение:** Шапка сайта (Секция 1), иконка лупы → модальное окно
- **Индексация:** Весь контент сайта (`collections.all`)
- **Результат:** Список материалов с заголовком, датой, кратким описанием

### 5.2. Поиск по разделу/рубрике (Rubric Search) — КЛЮЧЕВОЙ ДЛЯ НАВИГАЦИИ
- **Расположение:** Выпадающий список «Выберите нужный раздел/рубрику сайта» в шапке или сайдбаре
- **Фильтрация:** Только материалы выбранной рубрики (включая подрубрики)
- **Реализация:** Фильтрация индекса Lunr по полю `rubric` с поддержкой иерархии
- **Отображение:** Иерархический список с отступами для уровней вложенности (как на sit-salsk.ru)

**Пример структуры выпадающего списка:**
```html
<select name="rubric" id="rubric-selector" class="postform">
  <option value="-1">Выберите рубрику</option>
  <option class="level-0" value="abiturientam">1. АБИТУРИЕНТАМ</option>
  <option class="level-1" value="slovo-direktora">&nbsp;&nbsp;&nbsp;1.1. Слово директора</option>
  <option class="level-1" value="specialnosti">&nbsp;&nbsp;&nbsp;1.2. Специальности и профессии</option>
  <option class="level-1" value="priemnaya-kampaniya-2025">&nbsp;&nbsp;&nbsp;1.3. Приемная кампания 2025</option>
  ...
  <option class="level-0" value="vospitanie">4. ВОСПИТАТЕЛЬНАЯ РАБОТА</option>
  <option class="level-1" value="velikaya-pobeda">&nbsp;&nbsp;&nbsp;4.6.1. Великая Победа</option>
  ...
</select>
```

### 5.3. Поиск по тегам (Tag Search)
- **Расположение:** 
  - Клик по тегу в карточке материала
  - Виджет «Облако тегов» в Сайдбаре
- **Функционал:** Мгновенная фильтрация материалов по тематике

### 5.4. Комбинированный поиск (Advanced Search)
- **Расположение:** Расширенная форма поиска (опционально)
- **Параметры:** Рубрика + Теги + Дата + Тип материала
- **Реализация:** Композиция фильтров Lunr.js

### 🔧 Техническая реализация (Lunr.js)

**Важно:** Для поддержки русского языка необходимо подключить `lunr.ru.js` — официальный файл локализации Lunr.js для русской морфологии.

**Подключение русской локализации:**
```html
<!-- В шаблоне поиска (например, search-modal.njk) -->
<script src="/assets/js/lunr.min.js"></script>
<script src="/assets/js/lunr.ru.js"></script> <!-- Обязательный файл для русской локализации -->
<script src="/assets/js/search.js"></script>
```

**Генерация индекса при сборке:**
```js
// eleventy.config.js
config.addCollection("searchable", (collection) => {
  return collection.getAll().filter((item) => {
    return item.data.searchable !== false;
  });
});

config.addPlugin(eleventyPluginLunr, {
  collections: ["searchable"],
  fields: {
    title: { boost: 10 },
    content: {},
    tags: { boost: 5 },
    category: {}
  },
  ref: "url",
  outputPath: "/assets/js/search-index.json",
  // Важно: включить русскую локализацию
  language: "ru"
});
```

**Клиентский скрипт поиска:**
```js
// src/assets/js/search.js
(async function initSearch() {
  const indexResp = await fetch('/assets/js/search-index.json');
  const indexData = await indexResp.json();
  
  // lunr.ru.js должен быть подключён до этого скрипта
  const idx = lunr.Index.load(indexData.index);
  
  document.querySelector('[data-search-form]').addEventListener('submit', (e) => {
    e.preventDefault();
    const query = e.target.querySelector('[data-search-input]').value;
    const results = idx.search(query);
    renderResults(results, indexData.store);
  });
})();
```

**Установка lunr.ru.js:**
```bash
# Скачать файл локализации из официального репозитория Lunr.js
curl -o src/assets/js/lunr.ru.js https://raw.githubusercontent.com/MihaiValentin/lunr-languages/master/lunr.ru.js
```

| Требование | Реализация в проекте |

**Примеры корректных URL:**

```
❌ /Сведения/Документы/Антикоррупция/
```

**Настройка в Eleventy:**
```js
// eleventy.config.js — автоматический slugify для пермалинков
config.addFilter("slugify", (str) => {
  return str.toLowerCase()
    .replace(/[^\w\s-]/g, '')      // удалить спецсимволы
    .replace(/[\s_-]+/g, '-')      // пробелы/подчёркивания → дефис
    .replace(/^-+|-+$/g, '');      // убрать дефисы по краям
});
```

```yaml
# Front matter в контенте
---
title: Приёмная кампания 2025
permalink: /news/{{ title | slugify }}/
---
```

### Настройка .htaccess для кэширования

```apache
# === Кэширование статических ассетов (1 год) ===
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType text/css "access plus 1 year"
  ExpiresByType application/javascript "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
</IfModule>

# === Сжатие Gzip ===
<IfModule mod_deflate.c>

</IfModule>
```
