## 1. О Проекте

### 1.1. Цель
Создание современного, адаптивного, юридически корректного зеркала сайта `https://sit-salsk.ru/` для ГБПОУ РО "СИТ" (Сальский индустриальный техникум).

### 1.2. Требования к схожести
- **Минимум 70%** визуальной и структурной схожести с оригиналом (учитывая объем >10,000 файлов).
- Приоритет: **функциональная идентичность** > пиксель-перфект.
- Все изменения дизайна должны улучшать юзабилити, не ломая привычную навигацию пользователей.

### 1.3. Соответствие нормам РФ
Структура и содержание разделов должны соответствовать:
- 📋 **Приказ Рособрнадзора №1493** — требования к структуре официального сайта образовательной организации
- ♿ **ГОСТ Р 52872-2019** — доступность для слабовидящих (версия с увеличенным шрифтом, контрастом)
- 🔐 **152-ФЗ "О персональных данных"** — согласие на обработку, политика конфиденциальности
- 📚 **273-ФЗ "Об образовании"** — публикация сведений об образовательной организации

## 2. Глобальные принципы разработки

### 2.1. Адаптивная вёрстка (Mobile First)

```css
/* Базовый подход: стили для мобильных → медиа-запросы для больших экранов */
.component {
  /* Мобильные стили по умолчанию */
  padding: 1rem;
  font-size: 1rem;
}

/* Планшеты */
@media (min-width: 768px) {
  .component {
    padding: 1.5rem;
    font-size: 1.125rem;
  }
}

/* Десктопы */
@media (min-width: 1024px) {
  .component {
    padding: 2rem;
    font-size: 1.25rem;
  }
}
```

**Контрольные точки (Breakpoints Bootstrap 5):**
| Брейкпоинт | Ширина | Устройство |
|------------|--------|------------|
| `xs` | <576px | Малые телефоны |
| `sm` | ≥576px | Телефоны |
| `md` | ≥768px | Планшеты |
| `lg` | ≥992px | Ноутбуки |
| `xl` | ≥1200px | Десктопы |
| `xxl` | ≥1400px | Большие экраны |

**Требования:**
- ✅ Все компоненты тестируются на всех брейкпоинтах
- ✅ Нет горизонтального скролла на мобильных
- ✅ Область нажатия интерактивных элементов ≥44×44px на мобильных
- ✅ Шрифты масштабируются через `clamp()`: `font-size: clamp(1rem, 2.5vw, 1.5rem);`

### 2.2. Единые компоненты (DRY — Don't Repeat Yourself)

```
src/_includes/
├── base.njk              # Базовый шаблон (подключает header/footer)
├── partials/
│   ├── header.njk        # Секция 1: Шапка (единая для всех страниц)
│   ├── footer.njk        # Секция 6: Подвал (единая для всех страниц)
│   ├── sidebar.njk       # Секция 5: Сайдбар (условный рендеринг)
│   ├── card.njk          # Карточка материала (превью + теги)
│   └── breadcrumbs.njk   # Хлебные крошки (динамические)
└── layouts/
    ├── page.njk          # Макет для статических страниц
    ├── post.njk          # Макет для материалов (новости, документы)
    └── listing.njk       # Макет для списков (категории, теги)
```

> 💡 **Правило:** Изменение в `header.njk` автоматически обновляет шапку на всех страницах сайта.

### 2.3. Доступность (Accessibility / WCAG 2.1 AA)

**Обязательные требования:**
- ♿ Переключатель «Версия для слабовидящих»:
  - Увеличение шрифта (1.25×, 1.5×, 2×)
  - Высококонтрастная тема (чёрный фон / белый текст / жёлтые ссылки)
  - Отключение анимаций и переходов
  - Сохранение выбора в `localStorage`
- 🧭 Семантическая разметка:
  ```html
  <header>, <nav>, <main>, <article>, <aside>, <footer>
  ```
- ⌨️ Навигация с клавиатуры:
  - `Tab` — переход между интерактивными элементами
  - `Enter` — активация ссылки/кнопки
  - `Esc` — закрытие модальных окон, меню
  - Видимый фокус-индикатор для всех элементов
- 🔤 Альтернативные тексты:
  ```html
  <img src="logo.png" alt="ГБПОУ РО 'СИТ' — логотип техникума">
  ```

**Инструменты проверки:**
- [WAVE Web Accessibility Tool](https://wave.webaim.org/)
- [axe DevTools](https://www.deque.com/axe/devtools/)
- Lighthouse → Accessibility (цель: ≥95)

## 3. Структура страницы: 6 адаптивных секций

Каждая страница сайта строится из **6 логических секций** (сверху вниз). Их **адаптивное поведение** — строго определено, а **наполнение** — гибкое и зависит от типа страницы.

### 📱 Адаптивная матрица секций

| Секция | Десктоп (≥1024px) | Планшет (768–1023px) | Мобильный (<768px) |
|--------|-------------------|----------------------|-------------------|
| **1. HEADER** | Фиксированная шапка, горизонтальное меню, поиск в строке | Меню сворачивается в бургер, поиск в иконке | Бургер-меню, логотип + контакты в одну строку |
| **2. Контекстная** | Полная ширина, возможно с боковыми элементами | Элементы выстраиваются вертикально | Компактный вид, скрытие второстепенного |
| **3. Основной контент** | Сетка: контент 75% + сайдбар 25% справа | Сайдбар под контентом или в аккордеоне | Полная ширина, сайдбар в конце страницы |
| **4. Дополнительные блоки** | Отображаются в колонках рядом | Блоки выстраиваются вертикально | Сворачиваются в аккордеон или скрываются |
| **5. SIDEBAR** | Фиксированная правая колонка (sticky) | Под основным контентом | Внизу страницы, в аккордеоне |
| **6. FOOTER** | Многоколоночный (4–5 колонок) | 2–3 колонки | Одна колонка, элементы вертикально |

### 🔧 Принципы наполнения секций

#### Секции 1 и 6 (Header / Footer) — Единые компоненты
```njk
{# src/_includes/base.njk #}
<body>
  {% include "partials/header.njk" %}
  
  <main>
    {# Динамический контент страницы #}
    {{ content | safe }}
  </main>
  
  {% include "partials/footer.njk" %}
</body>
```
> ✅ Изменение в одном файле обновляет весь сайт.

#### Секции 2–5 — Гибкое наполнение
Наполнение определяется **типом страницы** через front matter или данные `_data/`:

```yaml
# Пример front matter для страницы категории
---
layout: listing.njk
title: Новости
sectionContext:
  breadcrumbs: [Главная, Новости]
  banner: /assets/img/news-banner.jpg
  filters: [дата, теги]
sidebar:
  show: true
  widgets: [search, tags, archive]
---
```

```njk
{# Условный рендеринг секций в шаблоне #}
{% if sectionContext %}
  <section class="section-context">{# Секция 2 #}</section>
{% endif %}

<main class="section-main">{# Секция 3 #}
  {{ content | safe }}
</main>

{% if additionalBlocks %}
  <section class="section-extra">{# Секция 4 #}</section>
{% endif %}

{% if sidebar.show %}
  <aside class="section-sidebar">{# Секция 5 #}
    {% include "partials/sidebar.njk" %}
  </aside>
{% endif %}
```

**Примеры наполнения по типам страниц:**

| Тип страницы | Секция 2 | Секция 3 | Секция 4 | Секция 5 |
|-------------|----------|----------|----------|----------|
| 🏠 Главная | Баннер, быстрые ссылки | Сетка новостей | Важные объявления | Популярные разделы |
| 📰 Список новостей | Фильтры, сортировка | Карточки новостей (превью) | Пагинация | Облако тегов, архив |
| 📄 Страница новости | Хлебные крошки | Полный текст + изображения | «Читайте также» | Теги, соц. кнопки |
| 📋 Раздел "Сведения" | Заголовок раздела | Список подразделов | — | Боковое меню подразделов |
| 📎 Страница документа | Хлебные крошки | Текст + вложения (PDF/DOC) | Связанные документы | Навигация по разделу |

## 4. Система Контента: Категории, Материалы, Теги

### 4.1. Иерархия контента

```
Категория (Раздел)
├── Страница категории (список материалов)
│   ├── Материал 1 (превью в списке)
│   ├── Материал 2
│   └── ...
│
Материал (Страница контента)
├── Заголовок (title)
├── Дата публикации (date)
├── Теги (tags: [новость, абитуриенту])
├── Категория (category: news)
├── Краткое описание (excerpt) — для превью
├── Полный контент (content) — для страницы
└── Вложения (attachments) — PDF, DOC, изображения
```

### 4.2. Типы страниц

#### 📋 Страница списка (Listing)
- **Шаблон:** `src/_includes/layouts/listing.njk`
- **Назначение:** Выводит сетку превью материалов выбранной категории
- **Компоненты:**
  - Фильтры (дата, теги)
  - Сортировка (по дате, по алфавиту)
  - Сетка карточек (`card.njk`)
  - Пагинация

#### 📄 Страница материала (Post)
- **Шаблон:** `src/_includes/layouts/post.njk`
- **Назначение:** Выводит полный контент одного материала
- **Компоненты:**
  - Заголовок, дата, автор
  - Основной текст (Markdown → HTML)
  - Вложения (кнопки скачивания)
  - Теги (кликабельные ссылки)
  - Блок «Читайте также»

### 4.3. Теги: отображение и функционал

**Отображение:**
- ✅ В карточке превью (внизу): `<span class="tag">новость</span>`
- ✅ В конце полного текста материала: блок «Теги: [...]»

**Функционал:**
- 🔗 Каждая метка — кликабельная ссылка на страницу фильтрации: `/tags/новость/`
- 📊 Страница тега выводит все материалы с этим тегом (пагинация)

**Пример front matter с тегами:**
```yaml
---
title: Приёмная кампания 2026
date: 2026-04-15
tags: [абитуриенту, приём, 2026]
category: news
---
```

> ⚠️ **Важно:** Теги указываются как массив `tags: []`, а не строка. Регистр не учитывается при фильтрации.

## 5. Поисковая система

Реализуется **три уровня поиска** на базе Lunr.js:

### 5.1. Общий поиск (Global Search)
- **Расположение:** Шапка сайта (Секция 1), иконка лупы → модальное окно
- **Индексация:** Весь контент сайта (`collections.all`)
- **Результат:** Список материалов с заголовком, датой, кратким описанием

### 5.2. Поиск по разделу (Section Search)
- **Расположение:**  Выпадающий список «Выберите раздел» в шапке
- **Фильтрация:** Только материалы выбранной категории
- **Реализация:** Фильтрация индекса Lunr по полю `category`

### 5.3. Поиск по тегам (Tag Search)
- **Расположение:** 
  - Клик по тегу в карточке материала
  - Виджет «Облако тегов» в Сайдбаре
- **Функционал:** Мгновенная фильтрация материалов по тематике

### 🔧 Техническая реализация (Lunr.js)

**Важно:** Для поддержки русского языка необходимо подключить `lunr.ru.js` — официальный файл локализации Lunr.js для русской морфологии.

**Подключение русской локализации:**
```html
<!-- В шаблоне поиска (например, search-modal.njk) -->
<script src="/assets/js/lunr.min.js"></script>
<script src="/assets/js/lunr.ru.js"></script> <!-- Обязательный файл для русской локализации -->
<script src="/assets/js/search.js"></script>
```

**Генерация индекса при сборке:**
```js
// eleventy.config.js
config.addCollection("searchable", (collection) => {
  return collection.getAll().filter((item) => {
    return item.data.searchable !== false;
  });
});

config.addPlugin(eleventyPluginLunr, {
  collections: ["searchable"],
  fields: {
    title: { boost: 10 },
    content: {},
    tags: { boost: 5 },
    category: {}
  },
  ref: "url",
  outputPath: "/assets/js/search-index.json",
  // Важно: включить русскую локализацию
  language: "ru"
});
```

**Клиентский скрипт поиска:**
```js
// src/assets/js/search.js
(async function initSearch() {
  const indexResp = await fetch('/assets/js/search-index.json');
  const indexData = await indexResp.json();
  
  // lunr.ru.js должен быть подключён до этого скрипта
  const idx = lunr.Index.load(indexData.index);
  
  document.querySelector('[data-search-form]').addEventListener('submit', (e) => {
    e.preventDefault();
    const query = e.target.querySelector('[data-search-input]').value;
    const results = idx.search(query);
    renderResults(results, indexData.store);
  });
})();
```

**Установка lunr.ru.js:**
```bash
# Скачать файл локализации из официального репозитория Lunr.js
curl -o src/assets/js/lunr.ru.js https://raw.githubusercontent.com/MihaiValentin/lunr-languages/master/lunr.ru.js
```

// eleventy.config.js — автоматический slugify для пермалинков
config.addFilter("slugify", (str) => {

    .replace(/[\s_-]+/g, '-')      // пробелы/подчёркивания → дефис
    .replace(/^-+|-+$/g, '');      // убрать дефисы по краям
});

### 10.9. Ошибки, которых следует избегать

| Ошибка | Последствие | Как избежать |
|--------|-------------|-------------|
| 🔁 Дубли страниц без canonical | Пессимизация в выдаче | Всегда указывать `rel="canonical"` |
| 📢 Переспам ключевыми словами | Фильтры поисковиков | Писать для людей, ключи — естественно |
| 🔗 Битые внутренние ссылки | Потеря веса страниц, плохой UX | Проверять через `npm run check:links` |
| 🖼️ Изображения без alt | Потеря трафика из поиска по картинкам | Заполнять alt для всех информативных изображений |
| 📱 Отсутствие мобильной версии | Понижение в мобильной выдаче | Использовать адаптивную вёрстку (Bootstrap 5) |
| ⏳ Медленная загрузка | Высокий процент отказов | Оптимизировать изображения, кэшировать статику |

### Оптимизации при сборке

```js
// eleventy.config.js — примеры оптимизаций

// 1. Минификация HTML (в продакшене)
if (process.env.NODE_ENV === 'production') {
  config.addTransform("htmlmin", require("./src/_filters/htmlmin"));
}

// 2. Оптимизация изображений (конвертация в WebP с фоллбэком)
config.addPassthroughCopy("src/assets/images", {
  filter: /\.(png|jpe?g|svg)$/i,
  transform: (content, outputPath) => {
    // Логика конвертации в WebP (требует sharp)
    return content;
  }
});

// 3. Разделение JS: общий код + модули по требованию
config.addPassthroughCopy("src/assets/js/main.js");
config.addPassthroughCopy("src/assets/js/search.js"); // Загружается только на страницах с поиском
config.addPassthroughCopy("src/assets/js/a11y-toggle.js"); // Загружается только если есть переключатель

// 4. Кэширование статики через .htaccess (настраивается в файле)
// См. .htaccess: ExpiresByType для ассетов с хешем — 1 год
```

### Настройка .htaccess для кэширования

```apache
# === Кэширование статических ассетов (1 год) ===
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType text/css "access plus 1 year"
  ExpiresByType application/javascript "access plus 1 year"
  ExpiresByType image/png "access plus 1 year"
  ExpiresByType image/jpg "access plus 1 year"
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType image/svg+xml "access plus 1 year"
  ExpiresByType font/woff2 "access plus 1 year"
</IfModule>

# === Сжатие Gzip ===
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css application/javascript
</IfModule>
```

> 💡 **Совет:** Для ассетов с хешем в имени (`style.abc123.css`) можно ставить кэш на 1 год. Для динамических файлов (`submit-form.php`) — не кэшировать.
