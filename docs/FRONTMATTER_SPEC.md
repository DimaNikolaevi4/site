# Спецификация Front Matter для сайта ГБПОУ РО "СИТ"

> 📄 **Файл:** `FRONTMATTER_SPEC.md`  
> 🔄 **Версия:** 2.0  
> 📅 **Обновлено:** Апрель 2026 (приведено в соответствие с реальной реализацией шаблонов и `src/_data/rubrics.yaml`)  
> 🎯 **Проект:** Модернизированное зеркало `https://sit-salsk.ru/` на базе Eleventy 3.x + Decap CMS

Этот документ описывает структуру метаданных (front matter) для всех Markdown-файлов проекта.  
Front matter располагается в самом начале файла между тройными дефисами `---` и используется движком Eleventy для генерации страниц, меню, хлебных крошек, поиска (Lunr.js) и редактора контента (Decap CMS).

---

## Общие правила

1. **Формат:** YAML.
2. **Расположение:** Первые строки файла `.md` / `.njk`, между `---` ... `---`.
3. **Кодировка:** UTF-8.
4. **Обязательные поля для всех страниц:** `title`, `layout`, `permalink`.
5. **Язык:** Все текстовые значения — на русском (кроме технических ключей и слагов).
6. **Структура URL:** `permalink` отражает иерархию рубрик, начинается и заканчивается слэшем `/`.
7. **Рубрикация:** Поле `rubric` содержит **код** рубрики из `src/_data/rubrics.yaml` (например, `"1"`, `"1.3"`, `"2.3.1"`). Для технических/служебных страниц (контакты, политика, документы общего назначения) допускается значение `"0"` — маркер «без рубрики».

## 1. Шаблон: Материал (Тип C — пост, новость, документ)

Используется для отдельных публикаций — новостей, документов, объявлений. Шаблон — `layouts/post.njk`.

```yaml
---
layout: layouts/post.njk
title: "Заголовок материала"
description: "Краткое описание для SEO (meta description), 150–160 символов."
date: 2026-04-18                # Дата публикации (ГГГГ-ММ-ДД), сортирует материал в списках
updated: 2026-04-20             # (опц.) Дата последнего изменения
author: "Администрация"          # (опц.) Автор материала
permalink: /news/zagolovok-materiala/
rubric: "1.3"                   # Код рубрики из src/_data/rubrics.yaml
category: "abiturientam"        # (опц.) Слаг родительского раздела для группировки
tags:
  - Новости
  - Абитуриентам
image: /assets/images/news/cover.jpg   # (опц.) Главное изображение / обложка
excerpt: "Короткий тизер для карточки материала в списке."  # (опц.)
attachments:                    # (опц.) Список вложений
  - name: "Памятка абитуриента"
    url: /uploads/pamyatka-2026.pdf
    size: "1.2 MB"
relatedCollection: news         # (опц.) Имя коллекции для блока «Читайте также»
relatedCount: 3                 # (опц.) Сколько материалов показать
---
```

### Пояснения к полям:

| Поле | Обязательное | Назначение |
|------|--------------|------------|
| `layout` | ✅ | Для материала — `layouts/post.njk`. |
| `title` | ✅ | Заголовок страницы (отображается в `<h1>` и `<title>`). |
| `permalink` | ✅ | Уникальный URL. Должен начинаться и заканчиваться `/`. |
| `description` | 🟡 | Мета-описание для SEO и соцсетей. |
| `date` | 🟡 | Дата публикации. Используется для сортировки и блока «Читайте также». |
| `updated` | 🟢 | Дата последнего изменения. |
| `author` | 🟢 | Автор материала. |
| `rubric` | 🟡 | Код рубрики из `src/_data/rubrics.yaml`. Используется для построения навигации, фильтрации поиска и хлебных крошек. |
| `category` | 🟢 | Слаг родительского раздела (например, `"abiturientam"`). |
| `tags` | 🟡 | Массив ключевых слов. Каждый тег — кликабельная ссылка `/tags/тег/`. |
| `image` | 🟢 | Главное изображение для превью и соцсетей. |
| `excerpt` | 🟢 | Тизер для карточки материала в листинге. |
| `attachments` | 🟢 | Массив вложений (`name`, `url`, `size`) — отображается в блоке «Вложения». |
| `relatedCollection` / `relatedCount` | 🟢 | Управляют блоком «Читайте также» в `post.njk`. |

## 2. Шаблон: Раздел (Тип B — индекс рубрики, страница раздела)

Используется для индексных страниц рубрик (`/abiturientam/`, `/vospitanie/`, …) и под-разделов (`/abiturientam/specialnosti/`).

**Основной шаблон** — `layouts/page-full.njk` (24 страницы): hero + хлебные крошки + сетка 70/30 с сайдбаром + опциональные секции about/news/popular.  
**Упрощённый** — `layouts/page.njk` (используется реже).  
**Спец-вариант** — `layouts/svedenija-page.njk` (для раздела «Сведения об ОО» по Приказу Рособрнадзора №1493, 18 страниц).

```yaml
---
layout: layouts/page-full.njk
title: Абитуриентам
description: "Раздел для будущих студентов — приёмная кампания, специальности, контакты приёмной комиссии."
permalink: /abiturientam/
rubric: "1"                     # Уровень 0: "1" / Уровень 1: "1.3" / Уровень 2: "4.7.2"
section: abiturientam           # (опц.) Слаг раздела для группировки и сайдбара
sectionTitle: Абитуриентам      # (опц.) Заголовок секции для hero и breadcrumbs
tags:
  - Абитуриентам
eleventyNavigation:             # (опц.) Регистрация в главном меню через @11ty/eleventy-navigation
  key: abiturientam
  parent: main
  order: 1
---
```

### Пояснения:

- **`layout`** — для разделов используйте `layouts/page-full.njk` (рекомендуется); `page.njk` — для упрощённых страниц без всех 8 секций.
- **`rubric`** — обязательно для разделов: код из `rubrics.yaml`. Уровни иерархии: L0 (`"1"`), L1 (`"1.3"`), L2 (`"2.3.1"`).
- **`section` / `sectionTitle`** — используются `hero.njk` и `breadcrumbs.njk` для отображения родительской группировки.
- **`eleventyNavigation`** — задействует плагин `@11ty/eleventy-navigation` для построения главного меню. Корневой ключ родителя — `main` (соответствует пунктам в `src/_data/menu.yaml`).

## 3. Шаблон: Статическая страница (контакты, спасибо, политика)

Для отдельных страниц общего назначения, не входящих в иерархию рубрик. Используется тот же `layouts/page-full.njk` (или `page.njk`); страница помечается как служебная.

```yaml
---
layout: layouts/page-full.njk
title: Контакты
permalink: /contacts/
rubric: "0"                              # Маркер «без рубрики» для служебных страниц
eleventyExcludeFromCollections: true     # Не попадает в коллекции и листинги новостей/рубрик
---
```

### Пояснения:

- **`rubric: "0"`** — конвенция проекта для служебных страниц, у которых нет места в иерархии рубрик. Фильтр `getRubricByCode` корректно отдаёт `null`, сборка не падает.
- **`eleventyExcludeFromCollections: true`** — стандартный механизм Eleventy: страница не индексируется коллекциями, не попадает в автоматические списки.
- Главное меню формируется из `src/_data/menu.yaml`, поэтому отдельных полей `showInMenu`/`menuLocation` во frontmatter не требуется.

## 4. Шаблон: Главная страница (Тип A)

Файл: `src/index.njk` (Nunjucks-шаблон, не `.md`). Все 8 секций собраны вручную через `{% include "components/..." %}`.

```yaml
---
layout: layouts/base.njk
title: Главная страница
description: "Официальный сайт Сальского индустриального техникума"
hideRubric: true                # Скрыть подзаголовок рубрики в hero
---
```

### Пояснения:

- **`layout: layouts/base.njk`** — главная использует базовый макет напрямую и сама управляет порядком секций.
- **`hideRubric: true`** — флаг для `hero.njk`: на главной не показывать строку с названием рубрики под чертой (только «ГБПОУ РО "СИТ"»).
- Hero-баннер, последние новости и прочие блоки на главной задаются прямо в разметке `src/index.njk` и читают данные из коллекций (например, `collections.news | reverse | first(3)`). Ручных полей `featuredPosts`/`heroBanner` нет.

Для поля `rubric` используется **код** (например, `"1.3"`). Для поля `category` используется **слаг** (например, `"abiturientam"`).

## Валидация Front Matter

Перед коммитом убедитесь, что:

1. ✅ Все даты — в формате `YYYY-MM-DD`.
2. ✅ `permalink` начинается и заканчивается слэшем `/`.
3. ✅ `layout` указывает на существующий файл в `src/_includes/layouts/` (`base.njk`, `page.njk`, `page-full.njk`, `post.njk`, `svedenija-page.njk`, `listing.njk`).
4. ✅ Поле `rubric` содержит корректный код из `src/_data/rubrics.yaml` (или `"0"` для служебных страниц).
5. ✅ `permalink` уникален в пределах сайта (не дублируется).
6. ✅ Для каждого информативного изображения в контенте задан `alt`.
7. ✅ Поле `title` уникально в пределах своей рубрики.

### Дополнительные правила для Decap CMS:

- При использовании Decap CMS front matter генерируется автоматически на основе `src/admin/config.yml`.  
  Поля коллекций в `config.yml` должны соответствовать этой спецификации.
- Для новых материалов поле `rubric` должно выбираться из предустановленного списка кодов (генерируется из `src/_data/rubrics.yaml`).
