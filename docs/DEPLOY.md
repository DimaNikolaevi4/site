# Инструкция по деплою на хостинг Beget

## 📋 Подготовка к публикации

### 1. Проверка сборки

Перед деплоем убедитесь, что сайт собирается без ошибок:

```bash
npm run build
```

**Ожидаемый результат:**
- ✅ 0 ошибок
- ✅ 0 предупреждений
- ✅ В папке `public/` появились все файлы

### 2. Проверка файлов готовности

Убедитесь, что в проекте присутствуют все необходимые файлы:

- [ ] `public/robots.txt` — правила для поисковиков
- [ ] `public/sitemap.xml` — карта сайта
- [ ] `public/404.html` — страница ошибки 404
- [ ] `public/styles/main.css` — стили с поддержкой доступности
- [ ] `public/assets/js/main.js` — скрипты с accessibility manager

> ⚠️ **Примечание:** Файл `submit-form.php` для формы обратной связи отсутствует на текущем этапе разработки (см. CHECKLIST.md, раздел 9.2 «152-ФЗ — форма обратной связи»).

## 🚀 Деплой на Beget

### Шаг 1: Вход в панель управления

1. Перейдите на https://hosting.beget.com
2. Войдите под своим логином и паролем

### Шаг 2: Открытие файлового менеджера

1. В панели управления выберите ваш сайт
2. Нажмите **«Файловый менеджер»**

### Шаг 3: Загрузка файлов

#### Вариант A: Через файловый менеджер (рекомендуется)

1. Перейдите в директорию вашего сайта (обычно `/home/{username}/{site_name}/public_html/`)
2. Удалите старые файлы сайта (если есть)
3. Загрузите **все файлы из папки `public/`**:
   - `index.html`
   - `about/`, `svedenija/`, `news/`, `contacts/`, `documents/`
   - `abiturientam/`, `bezopasnost/`, `vospitanie/`, `sotrudnichestvo/`
   - `studentam-i-roditeljam/`, `uchebno-metodicheskaja-rabota/`
   - `professionaly-2026/`, `thank-you/`
   - `search/`, `pages/` (шаблонные страницы)
   - `content/` (страницы категорий и материалов)
   - `assets/`, `styles/`
   - `admin/` (Decap CMS)
   - `robots.txt`, `sitemap.xml`, `404.html`

> ⚠️ **Важно:** Файл `submit-form.php` для формы обратной связи пока не загружен, так как форма находится в разработке (см. CHECKLIST.md раздел 9.2.5). Не включайте этот пункт в загрузку до завершения разработки.

#### Вариант B: Через FTP

1. Подключитесь по FTP:
   - **Хост:** `{site_name}.beget.ru`
   - **Логин:** `{username}`
   - **Пароль:** ваш пароль от хостинга
   - **Порт:** 21

2. Перейдите в папку `public_html/`
3. Загрузите все файлы из локальной папки `public/`

### Шаг 4: Настройка PHP формы

> ⚠️ **Статус:** Форма обратной связи находится в разработке. Этот шаг следует выполнять только после завершения реализации формы (см. CHECKLIST.md раздел 9.2.5).

Когда форма будет готова, файл `submit-form.php`:
- Должен быть загружен в корень сайта
- Должен иметь права доступа `644`

Проверка прав:
```
-rw-r--r-- submit-form.php
```

### Шаг 5: Настройка 404 страницы

В панели Beget:
1. Перейдите в раздел **«Сайты»** → **«404 страница»**
2. Выберите **«Использовать свою страницу»**
3. Укажите путь: `/404.html`
4. Сохраните настройки

### Шаг 6: Проверка robots.txt

1. Откройте https://{ваш-домен}/robots.txt
2. Убедитесь, что файл доступен и содержит правильные правила

### Шаг 7: Отправка sitemap.xml в поисковики

#### Яндекс.Вебмастер
1. Перейдите на https://webmaster.yandex.ru
2. Добавьте свой сайт
3. В разделе **«Индексирование»** → **«Файлы Sitemap»** добавьте:
   ```
   https://{ваш-домен}/sitemap.xml
   ```

#### Google Search Console
1. Перейдите на https://search.google.com/search-console
2. Добавьте свой сайт
3. В разделе **«Файлы Sitemap»** добавьте:
   ```
   sitemap.xml
   ```

## 📁 Структура `docs/` на хостинге — документы вне репозитория

> Апрель 2026: крупные PDF/DOC/ZIP файлы (~423 МБ) перенесены из репозитория на хостинг в папку `docs/`. Они **не входят в сборку Eleventy** и не хранятся в `src/assets/uploads/` (кроме контентных изображений). Подробнее: `docs-upload.README.md` в корне проекта, чеклист 7.0 в `CHECKLIST.md`.

### Структура `docs/` на хостинге Beget

```
public_html/                           ← document root на Beget
├── index.html                         ← статические страницы Eleventy (из public/)
├── assets/
├── styles/
├── ...
└── docs/                              ← документы вне репозитория (НЕ из сборки)
    ├── dokumenty/       (304 файла, 322 МБ — документы + антикоррупция)
    ├── vsoko/           (90 файлов,   84 МБ — ВСОКО)
    ├── struktura/       (33 файла,   9.7 МБ — структура и органы управления)
    ├── pedagog/         (16 файлов,  3.6 МБ — педагогический состав)
    ├── priemnaya-kampaniya-2026/  (15 файлов, 2.4 МБ)
    ├── mezhdunarodnoe/  ( 9 файлов,  1.6 МБ — международное сотрудничество)
    └── podacha-elektronnaya-pochta/  ( 6 файлов, 336 КБ — бланки заявлений)
```

**Базовый URL:** `https://xn----8sbwke6acce8h.xn--p1ai/docs/`  
**Пример:** `https://сит-сальск.рф/docs/dokumenty/устав.pdf`

### Важно при обновлении сайта

- Папка `docs/` на хостинге **не перезаписывается** при деплое (`deploy.sh` очищает `public_html/` только от статических файлов Eleventy, но **не трогает `docs/`**).
- При добавлении нового документа — залить файл напрямую в нужную подпапку `docs/` через FTP/SCP.
- При обновлении ссылок на документы в шаблонах — использовать абсолютный URL: `https://xn----8sbwke6acce8h.xn--p1ai/docs/<папка>/имя-файла.pdf`.
- 301-редиректы со старого пути `/assets/uploads/*` → `/docs/*` настроены в `.htaccess` (задача 7.0.3.1 в `CHECKLIST.md`).

## 🔧 Обновление сайта

Для обновления контента:

1. Внесите изменения в файлы в папке `src/`
2. Выполните сборку:
   ```bash
   npm run build
   ```
3. Загрузите изменённые файлы из `public/` на хостинг
4. Очистите кэш браузера (Ctrl+F5)

## 🆘 Решение проблем

### Сборка завершается с ошибкой
```bash
# Очистите кэш npm
npm cache clean --force

# Переустановите зависимости
rm -rf node_modules package-lock.json
npm install

# Попробуйте собрать снова
npm run build
```

### Форма не отправляется
1. Проверьте, что `submit-form.php` загружен
2. Проверьте права доступа (должны быть 644)
3. Проверьте логи PHP на хостинге

### Стили не применяются
1. Проверьте путь к CSS файлу в HTML (должен быть `/styles/main.css`)
2. Очистите кэш браузера
3. Проверьте, что файл `main.css` загружен в `/styles/`

### Страница 404 не отображается
1. Проверьте настройку в панели Beget (раздел «404 страница»)
2. Убедитесь, что файл `404.html` загружен в корень сайта
